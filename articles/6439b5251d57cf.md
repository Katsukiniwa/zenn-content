## 概要

## 書籍について

[コンピュータシステムの理論と実装 第2版](https://www.oreilly.co.jp/books/9784814400874/) からの引用です

> コンピュータシステムをゼロから作って学ぶベストセラー書の改訂第2版。コンピュータを理解するための最善の方法はゼロからコンピュータを作ることです。コンピュータの構成要素は、ハードウェア、ソフトウェア、コンパイラ、OSに大別できます。本書では、これらコンピュータの構成要素をひとつずつ組み立てます。具体的には、NANDという電子素子からスタートし、論理ゲート、加算器、CPUを設計します。そして、アセンブラ、仮想マシン、コンパイラ、OSなどを実装しコンピュータを完成させて、最後にその上でアプリケーション（テトリスなど）を動作させます

NANDから始めて最後は自力でOSやプログラミング言語までを実装していくという書籍です。

## なぜこの記事を書こうと思ったのか

ネットで「コンピュータシステムの理論と実装」に取り組んだ人の記事は全て完走した人の記事ばかりで、こんなに難しい書籍なのに挫折した人の記事がないのはおかしい、何が自分に足りないのか知りたいと思ったので書いてみました。
この知識が足りてないよ、とか単純に考える時間が足りてないなど忌憚なき意見をコメント等で頂ければ幸いです。

## なぜやろうと思ったのか

自分は大学でCS系の学部を卒業しておらず、なんなら中退していてコンピュータサイエンスについては恥ずかしながら全くの無知です。これまでの業務では

- Ruby on RailsやTypeScriptを使ったバックエンド開発
- Reactを使ったフロントエンド開発
- AWS, GCPを使ったインフラリソースの用意

といった感じであくまでプログラミング言語やインフラを使う側の開発しかしてきていませんでした。がっつりインフラに関われるだけの技術力もなかったので、低レイヤーやコンピュータリソースへの理解を深めないまま数年が経過してしまいました。これに対してずっとコンプレックスはあったものの、どうしたら低レイヤーの知識を獲得できるのか分からず試行錯誤して挫折するのが毎回の流れでした。

[【最新技術に振り回されない】 低レイヤーに強くなるための鉄板コンテンツ集](https://qiita.com/aaaaaaa8888/items/51c8084c00853d36cd01)

他の方の書籍レビューでも「これは図が豊富で挫折せずに読み切れました！」とあったので、流石にこれなら自分でも挫折せずに読み切れるだろうと思って読んでみたのですが、初めての用語や概念が多すぎて理解できませんでした。。。ちなみにその時のscrapが↓です。2章まで読み終わって挫折してますね。3章に入って `スケジューラ` や `コンテキストスイッチ` が出てきて何度読んでも「つまりこれは何？」と自分の言葉で説明できるレベルで理解することができませんでした。さすがに自分の頭の悪さに落ち込みました。この書籍で挫折してる人をネットで探した限りでは見つからなかったため、この後どうやって低レイヤーを勉強したら良いのか分からずひたすら焦って時間を溶かすだけの日々が続きました。

[「[試して理解] LINUXの仕組み」読書メモ](https://zenn.dev/katsukiniwa/scraps/f7985a23b31844)

なぜ理解できないのか・挫折してしまうのかを考えたところ、普段新しいプログラミング言語やFWの勉強するときは自分で手を動かして動作確認してエラーが起こったらどこが間違ってるのかを調査・修正してというフィードバックループを回しているのに対して、今回は書籍を読むのがメインで自分で手を動かせていないからだと仮説を立てました。
手を動かせるハンズオン形式の書籍がないか探したところ、今回の記事の主題である「コンピュータシステムの理論と実装」に出会いました。

## 1章から(自分にとっては)めちゃめちゃ難しかった

「コンピュータシステムの理論と実装」を完走した人の記事をいくつか読んだところ、1~3章は全然難しくないよ〜、という感想が多かったので「じゃあサクッと終わらせるか」と楽観視していました。しかし実際にやってみたところ、、、1章から全然わかりませんでした。誇張抜きで1問も解けませんでした。内容を知らない人向けに(正しく説明できるか不安ですが)説明しますと、1章では15個の論理ゲートを組み立てます。論理ゲートとは任意の数の0,1の入力値に対して様々なパターンで0,1を出力できるようにする回路のことです。詳細は書籍を読んでください🙏。

複数あるゲートのうちNANDだけは与えられているのでこれを使ってNotやOr, Xor、複数入力ゲートなど全15個のゲートを組み立てます。ただ組み立てるだけだから簡単そうなのですが、これが自分にはとてつもなく難しい課題でした。高校数学の論理と集合のような分野でどう組み合わせたら課題の論理ゲートのような入出力になるのか考えても考えても思いつきませんでした。実はこの書籍には3,4回挑戦して1章で挫折していました。最近5回目の挑戦をして、たまたま最初の課題であるNot, Andゲートを自力で組み立てることができたのでなんとか気合いで他の論理ゲートも組み立てて1章を完走する事ができました。参考までに自分の1章の実装を置いておきます。

https://github.com/Katsukiniwa/nand2tetris/tree/main/projects/1

## 2章はもっと難しかった

2章は1章で組み立てた論理ゲートを活用して算術論理演算機と呼ばれるものを組み立てます。つまり1章を理解してクリアしないと絶対に2章には挑戦できないのです。当然、1章を土台としてその上に乗っかる形の課題なので難易度は上がったように感じました。この時、どの回路を使えば課題の通りの出力になるのか頭で考えても分からなかったのでとにかく書き出して組み立てた時のメモがこちらです。

![alt text](/images/image.png)

わかる人が読んだらわかるのですが、これはめちゃ頭の悪い人のアプローチです。。。実際 `projects/2/FullAdder.hdl` の自分の回答と模範解答を比較しましょう。

**自分**
```
CHIP FullAdder {
    IN a, b, c;  // 1-bit inputs
    OUT sum,     // Right bit of a + b + c
        carry;   // Left bit of a + b + c

    PARTS:
    And(a=b, b=c, out=out1);
    Not(in=c, out=notc);
    And(a=a, b=notc, out=out3);
    Not(in=out3, out=out4); //*
    And(a=a, b=out4, out=out5); // *2
    Not(in=b, out=notb);
    And(a=notb, b=out5, out=out7);
    And(a=b, b=out3, out=out8);
    Or(a=b, b=out3, out=out9);
    Or(a=out7, b=out8, out=tmp);
    Or(a=tmp, b=out1, out=carry);
    And(a=a, b=notb, out=out10);
    And(a=out10, b=out3, out=out11);
    And(a=out1, b=out5, out=out12);
    Or(a=out11, b=out12, out=out13);
    And(a=b, b=notc, out=out14);
    And(a=c, b=notb, out=out15);
    Not(in=a, out=nota);
    And(a=nota, b=out14, out=out16);
    And(a=nota, b=out15, out=out18);
    Or(a=out16, b=out18, out=out20);
    Or(a=out13, b=out20, out=sum);
}
```

**模範解答**
```
CHIP FullAdder {
    IN a, b, c;  // 1-bit inputs
    OUT sum,     // Right bit of a + b + c
        carry;   // Left bit of a + b + c

    PARTS:
        HalfAdder (a=a, b=b, sum=s1, carry=c1);
        HalfAdder (a=s1, b=c, sum=sum, carry=c2);
        Or (a=c1, b=c2, out=carry);
}
```

ちゃんと書籍の説明を読んで過去に組んだ回路を活用できないか考えろって話ですね。。。ただ模範解答を読んでも「なぜこれでテストが通るのか？」が分からずひたすらClaude Codeに聞きました。聞いてなんとなく理解できたものの「これを自力で思いつける人は天才では・・・？自分は絶対に思いつけなかった。自分と解けた人の差はなんだろうか？」と悩んで時間を溶かすだけの日々が続きました。

## 3章に挑戦中

泣いてもネガティブになっても仕方がないので毎日夜にちょっとずつ3章に取り組んでいます。進捗あればまた別記事でアウトプットしようと思います。

## 最後に

まだ1,2章しか取り組んでいないのにもう終わったかのように振り返っていますが、まだ残り11章あるんですよね...しかもこれよりも難しい章が...。ただこの書籍を完走して理解しないと他の低レイヤー、インフラ系の書籍を読んでもチンプンカンプンで終わってしまうので踏ん張りたいと思います。
この書籍を完走できたら [詳解 システム・パフォーマンス 第2版](https://www.oreilly.co.jp/books/9784814400072/) を読めるようになるかな〜、と妄想しています。なんとしても「詳解 システム・パフォーマンス」を読み切って自信を持ってインフラに取り組めるようになりたい。そしてSREになりたい。そう思っています。以前お世話になった方に「詳解 システム・パフォーマンス」をお勧めしていただいたものの、全く理解できず、どうしたら理解できるようになるのかも分からず途方に暮れた情けない経験があります。今度こそ「コンピュータシステムの理論と実装」を完走して「詳解 システム・パフォーマンス」を読み切れるよう頑張りたいです。
