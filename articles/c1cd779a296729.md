# はじめに

Claude Code(コーディングエージェント？)で自分が分からないことを雑にまとめました。スクラップに書くべき内容かもしれませんが、なんとなくideaとして書こうという気持ちになったのでideaとして書きます。

# 筆者のClaudeの使い方

筆者はClaude Codeについて分からないことだらけですが、「分からないだらけのくせにどうやってClaude Code使ってるんや？」と気になった方もいらっしゃるかもしれないので参考までに筆者の普段のClaude Codeの使い方(= よく使うスキル)をパターン別に整理しました。

## 実装の場合

### 新機能実装(feat)の場合

[obra/superpowers](https://github.com/obra/superpowers)の `/brainstorming`を使うことが多いです。困ったらこれを呼び出してClaude Codeに自分が実装したい機能を深掘りしてもらいます。

### バグ調査(bugfix)の場合

[garrytan/gstack](https://github.com/garrytan/gstack)の `/investigate` を使います。本番環境で起こったエラーを調査したい場合、ログが残っていると調査が捗るのでSentryを導入した上で[Sentry MCP](https://mcp.sentry.dev/)に接続されていると良いかもです。

### リファクタリング(refactoring)の場合

リファクタリングの規模にもよるのですが、全体、つまりリポジトリ全体レベルで見直してリファクタリングしたい場合は[mattpocock/skills](https://github.com/mattpocock/skills)の `/improve-codebase-architecture`をまず呼び出してAsIs/ToBeの叩き台を作成してもらいます。ペラいちのHTMLが作成されるのでそれを読みつつ自分でちょこちょこ修正を加えてADRを作成します。

#### 余談
リファクタリングで言うと[ciembor/agent-rules-books](https://github.com/ciembor/agent-rules-books)も自分は使っています。これは名著の要約をruleにおいて実装を安定させよう！と言う試みのリポジトリです。自分はClean Architecture, レガシーコード改善ガイドのruleを置くことが多いです。効果を定量的に計測したことはないですが、おまじないとして置いています。

### レビュー系(review)の場合

[garrytan/gstack](https://github.com/garrytan/gstack)に `/plan-xxx-review`のスキルがあるのでデザインや実装など必要に応じた分野のスキルを呼び出しています。自分は実装のレビューを頼むことが多いので `/plan-eng-review` を呼び出すことが多いです。自分では気付かなかった観点・懸念事項を優先度つきでリストアップしてくれるので助かります。

### プロジェクト立ち上げの場合

[garrytan/gstack](https://github.com/garrytan/gstack)の `/office-hours` を使います。ちょこちょこ自分のアイデアをPoCレベルでサクッと立ち上げたいことがあるのでその時は `/office-hours` を使います。

## デザインの場合

完全に0→1開発であれば自分でデザインも考える必要があります。その場合まずはDESIGN.mdの作成に着手します。[kzhrknt/awesome-design-md-jp](https://github.com/kzhrknt/awesome-design-md-jp)にまとまっているのでこれを参考にオリジナルのDESIGN.mdを作成します。

全体のサイトデザインについては[Pencil](https://www.pen.dev/)か[Stitch](https://stitch.withgoogle.com/)を使います。なんとなくPencilの方が使いやすいので自分はPencilを使うことが多いです。しかしStichは1つのプロンプトで同時に3パターン作成してくれる機能があるのでとにかく数を出して比較したいと言うケースではStitchの方が良いと思います。

# 分からないこと

さて、本題の自分がClaude Codeを使っている上で分からないこと一覧です。

- UIのAI Slop対応
  - UIからどうやってAI臭をなくすか、最初からそもそも最初からどうやって発生させないようにするか
- スキルの作り方
  - 自分で0からスキルを作ったことがない
  - skill-creatorで作るらしい、しか知らない
- Claude Codeのベストプラクティス
  - そもそも知らない機能がたくさん
  - 公式ドキュメントを読まないとと思いつつ数ヶ月...
- ハーネスエンジニアリング・ループエンジニアリング・SDD(仕様駆動開発)
  - 本当に用語しか知らない
  - どうやって自立型開発の基盤を構築するの？
    - いまだにターミナルにぽちぽちプロンプト打ってる状態から脱却したい
    - チケット切ったらPR立つレベルまで持っていきたい
    - 理想は [Hermes Agent と Slack で設計し、Linear のチケットから Draft PR まで作成するワークフローの素振りをした](https://azukiazusa.dev/blog/hermes-agent-slack-workflow/) です
  - SDDのやり方全然分からない
- CI落ちたままPR作成する問題
  - いまだにCI落ちたままPR作成してしまう
  - hookで防げるはずだけどなんでだろうね？
- QAどうやってやる？
  - E2Eで対処するのはなんか違う気がする・・・？
  - E2Eがflakyなのは事実
  - QA専門のサブエージェントをどうやって作るのか知りたい
- URL渡しても全部読んでくれないらしい問題
  - [あなたのClaude CodeのWebFetch、実はWebをちゃんと読んでいない](https://zenn.dev/zhizhiarv/articles/claude-code-webfetch-haiku-summary)
  - ↑らしい、みんなどうしてるんだろう
  - [Give me Markdown](https://give-me-markdown.com) とかを使ってmarkdownに変換して読み込ませれば精度上がるんじゃなかろうかと適当に考えている
- Claude Codeを活用したレガシーコードの退治方法
  - Claude Code関係ないけど...
  - 事例はたくさんあるんだけど調べてもいまいち具体の方法が載ってない
    - 自社ドメインの中核に関わるから当然だけど...

こう見ると全然理解できていないことがわかりますね。リポジトリの `.claude`ディレクトリを完璧にするまでにはまだまだ時間がかかりそうです。
